# NeoX 0.5：MMD 动作适配实验版

这版把 MMD 身体网格和蒙皮权重适配到游戏原骨架。输出仍是目标角色的同名 CMesh、GIM、MTG 和配套贴图；游戏继续使用原角色动作。

**目前是基础蒙皮适配，不是完整 PMX/VMD/物理转换。已完成本地测试，尚未完成此版本的游戏动作验收。**

## 安装

1. 保存当前 Blender 工程。
2. 在 Blender 插件设置里，从磁盘安装 `C:\WORK\Chatgpt\NeoX_皮肤导出插件_v0.5.0.zip`，启用“NeoX 皮肤导出与回装”。它是原插件的升级版，模块名相同，覆盖旧版即可。
3. 重启 Blender，三维视图按 **N → NeoX 导出**，应显示 **NeoX 模型替换 0.5**。

原来的 NeoX 模型导入插件仍可保留。本功能直接读取目标原始文件建立骨架，无需再把目标模型导入场景。

## 新模型按这六步做

| 步骤 | 操作 | 看到什么才继续 |
|---|---|---|
| ① 选源模型 | 选中 MMD 的身体、衣服、头发等网格，点“使用当前选择的模型” | 网格都属于同一个源骨架，不能混入原游戏角色 |
| ② 选目标 | 选择未修改的原始 `.cmesh`；同目录需要同名 `.gim`、`.mtg` 和依赖贴图 | 选择正确的局外 / 局内位置 |
| ③ 选方式 | 将“处理方式”设为 **MMD 动作适配（实验）** | 不要继续使用默认“自动判断”，它仍会把外来模型作为静态展示 |
| ④ 准备副本 | 点“准备动作副本” | 自动识别骨骼、调整体型和绑定姿势、转换权重、识别贴图与 UV |
| ⑤ 检查动作 | 选中生成的 `NeoX_MMD动作适配副本`，小键盘 `/` 隔离查看；点“测试关节”，检查后点“恢复姿势” | 手臂、膝盖能分别弯曲，没有明显拉丝、左右串权重、肩胯塌陷 |
| ⑥ 导出 | 点 **导出当前适配副本** | 后台成功并通过本地回读后，才显示安装按钮 |

“测试关节”是 Blender 中的简单转动测试，**不是游戏实际动画**。导出读取静止网格，不会把这个测试姿势写成游戏的绑定姿势。

## 找不到骨骼时

点“识别骨骼对应”，展开“骨骼对应表”。带 `*` 的骨盆、脊柱、头部、双臂和双腿等项目必须补全：上面选源 MMD 骨骼，下面填写目标游戏骨骼的准确名称。

支持常见日文 MMD 名称、`.L/.R` 左右后缀、部分英文名称和游戏 Biped 名称。足 D 骨骼可复用对应腿部映射；不同命名、不明确的映射会要求手动处理，不按空间最近位置猜骨骼。

“保存配置 / 读取配置”可以复用对应表。配置与源骨架名称、层级以及目标文件哈希绑定；切换到不匹配的骨架或目标时会拒绝套用。

## 头发、裙摆和形态键

- 默认开启“附属骨骼随已映射父骨骼（无物理）”：例如没有对应游戏骨骼的头发随头部，衣物随其已有的已映射祖先。具体回退列表和权重占比写在工程 `reports/retarget.json`。
- 回退占比包含辅助骨骼、捩骨和衣发骨骼，**不等同于无法显示的模型比例**；这些部位会显示，但其独立运动被简化。
- 关闭上述选项后，有无法对应的加权骨骼就停止处理，避免静默简化。
- 当前要求表情形态键归零；只使用 Basis。当前姿态、IK 和 PMX 物理结果不会作为网格姿势烘入。
- 不转换 PMX 刚体 / 关节、VMD 动作、表情动画，也不自动生成游戏附属物理配置。

## 需要手工微调时

只修改新生成的 **动作适配副本**，在编辑模式修正肩、胯、袖子等网格，或用权重绘制修正蒙皮。之后直接点“导出当前适配副本”。

**不要编辑生成骨架的静止位置、方向、层级或骨骼编号。** 插件仍执行原生骨架校验，误改后会停止导出。

重新点“准备动作副本”会从源模型另建副本，不会保留上一次副本的手工微调。原 MMD 保留在场景中；自动适配不修改原网格、权重和骨架。

修改对应表、源模型选择或目标后，需要重新准备；旧结果不会继续作为可安装版本使用。

## 贴图与容量边界

沿用 0.3.2 / 0.4 的实际颜色 UV 追踪、基础贴图识别、透明通道、双面设置和后台 ASTC 编码。界面保持实体显示，以规避之前 MMD 材质预览触发的 Blender 崩溃。

完全重叠的球面高光层，只有位置、面以及归一化蒙皮权重都一致时才允许跳过。复杂 Toon、球面高光和其他节点并不等价于游戏着色器，当前仍用已支持的简单颜色模板近似显示。

仍限已支持的 v4 / flag 4、5 / 单分段 CMesh；骨架最多 254 根；UV 和法线拆分后的输出顶点必须少于 65536。不支持的目标材质模板会停止，不保证任意 MMD 和游戏模型都可自动转换。

## 放入模拟器

导出完成后，点 **备份并安装到 MuMu**。插件使用该工程的目标资源目录，先备份、再安装并校验。MuMu 路径、实例编号和游戏包名在插件偏好设置中配置。

例：150 局外目标对应 `/sdcard/Android/data/com.netease.fr26/files/netease/frxy/res/char/charselect/00150/`。应安装导出包内整套配套文件，不能只替换 `.cmesh` 或只替换一张纹理。

安装后重新启动单机客户端，检查待机、转身、手脚与衣物；局内资源需要单独导出并验证移动、普攻、技能、受击、死亡。出现异常可点“恢复安装前版本”。本次制作插件没有自动安装到模拟器。

“新皮肤资源”只负责生成文件，不会自动增加游戏皮肤选择入口。

# NeoX 模型替换 0.4.0

## 日常使用：三个步骤

安装 NeoX_皮肤导出插件_v0.4.0.zip 后重启 Blender。三维视图按 N，打开“NeoX 导出”，默认显示“引导流程”。

1. **选模型**：选中一个或多个模型网格，也可以选模型根物体或骨架，点击“使用当前选择的模型”。检查显示的网格名称，避免把原游戏角色和外来角色同时选入。自动收集根物体的可见子网格，排除刚体碰撞物。
2. **选目标**：选择要替换的角色未修改的原始 CMesh，同目录须有同名 GIM、MTG；选择“局外展示”或“局内模型”。角色编号和目标目录从原文件推导，不固定到任何一个角色。
3. **生成替换包**：点击“生成替换包（自动准备）”。插件自动建立 / 复用该目标工程、制作工作副本、处理材质和 UV、检查并后台导出。成功后点击“备份并安装到 MuMu”，重新打开游戏检查效果。

默认工程保存在 C:\WORK\Chatgpt\SkinProjects，可在“更多选项”修改。MuMu 路径仍在插件偏好设置中配置一次；更换实例时对应修改实例编号。

## 自动流程如何选择

- 同一原始资源导入的 NeoX 骨架：使用原生模式。复制并合并所选网格，保留原骨架权重，再校验骨骼、材质分组和数据。默认沿用游戏材质；Blender 节点改色需要到高级模式确认贴图。
- 其他模型：静态展示。支持目前可识别的 MMD Base Tex 或 Principled Base Color 图片连接，逐材质追踪 UV，再转换颜色图。可以同时处理身体、头发、衣服等多个网格，但不自动适配肢体动画。
- 多个模型网格可以使用不同的渲染 UV 名称；先分别整理再合并，避免混用活动辅助 UV。
- “更多选项”允许明确选择原生 / 静态模式。强制原生遇到不同源骨架时会停止，不会偷偷降级为静态。

所有几何处理在工作副本中进行，源网格、UV 和材质节点保留。为规避已发现的 MMD 预览崩溃，会将三维视图切到实体显示。

## 出现问题时

缺贴图、不支持的坐标变换、目标格式不支持、无法确定材质来源等问题，会集中显示在“生成与安装”区域，错误优先。完整记录在目标工程的 workflow.json。只想先检查时，可以点击“只诊断并准备”。

后台还会做严格序列化和回读验证。超过单分段顶点容量等问题可能在后台停止；失败时不会产生可安装版本，界面会显示失败原因。

复杂节点、纯程序材质、未识别的颜色连接等不会被猜测转换。需要人工调整时切到“高级设置”，保留原有各项操作。高级手动配置后请用高级界面的导出按钮；引导界面的生成按钮会重新从源模型自动配置。

## 重复使用与版本

同一个目标皮肤复用工程和安装备份记录。每次生成都会从记录的源网格制作新的导出副本，输出在独立任务目录中，不覆盖源模型或旧导出文件。

换模型时重新点击“使用当前选择的模型”；改目标时重新选择原 CMesh。改变输入会清除旧输出入口，防止误装其他模型的旧包。安装的是最近一次成功生成的包；修改源模型后应重新生成。

安装遇到未知设备版本时，先核对并用“更多选项”下的“备份当前版本为基线”保存，再安装。恢复按钮恢复该工程记录的安装前版本。自动生成不会自动安装到游戏。

## 新皮肤资源

在“更多选项”中把输出用途改为“新皮肤资源（仅生成文件）”，填写新名称与新目录。仍使用同一自动流程，但新资源不显示同名安装按钮；游戏菜单入口必须另行配置。

## 当前范围

一套流程可反复处理不同模型与不同角色目标；一次任务对应一套 CMesh/GIM/MTG 配套资源。独立武器、伙伴等多套 CMesh 仍需分别生成，尚未实现整目录批量替换。

本版未新增跨骨架自动动作适配、复杂 MMD 高光还原或多分段写入。支持的底层格式范围仍为现有写入器的 v4、flag 4/5、单分段等限制。局内与局外需要分别验证。

# NeoX 角色皮肤回写 0.3.2

## 0.3.2：修复 MMD 导出大片纯色

本次游戏异常的原因已经定位：制作静态副本时使用了编辑器选中的辅助 UV1；颜色节点实际使用渲染 UVMap。之前的二进制回读只能确认文件正确写入，不能证明选中的 UV 与图片实际连接一致。

现在仍然只需点击“一键配置 MMD 贴图（安全模式）”，再导出。插件追踪颜色图片的实际 UV 连接，支持 UV Map、隐式渲染 UV、Texture Coordinate 的 UV、Reroute 和节点组直连。按材质合并为 NXSE_ColorUV；多个材质可以来自不同 UV 层。无法等价解释的坐标变换会停止并要求先烘焙，不会猜测。

制作静态副本时，留空默认取渲染 UV；导出前与后台导出都会检查 MMD 颜色 UV 是否一致，错误的旧副本需要重新一键配置。

默认启用“跳过完全重叠的球面高光层”。仅对加法球面层逐面验证位置、面数和绕序完全重复后，在导出时略过；原模型的面和材质不删除。导出前会再次验证，模型变动使证明失效时停止。关闭该选项可以保留这层，但通用颜色材质不能还原球面高光。读取 MMD Double Sided 设置用于双面输出。

本次梦见月瑞希替换 00150：20 个材质自动配置，跳过与髮完全重复的髮+，实际输出 3 张颜色 ASTC。已在 MuMu 内备份并安装，截图确认眼睛、衣服花纹、发饰和头发细节恢复。

仍为静态绑定：整个模型会跟随目标骨骼倾斜，尚未适配肢体动画和完整 MMD 光照。仅本例贴图显示经过客户端检查，不代表所有复杂模型都兼容。当前游戏测试记录见 mmd150_crash_fix 下的截图与新工程 verified_install.json。


## 0.3.1：外来 MMD 的简化用法与选图闪退规避

建立目标角色工程、制作静态副本后，只需：

1. 点击 **一键配置 MMD 贴图（安全模式）**。
2. 点击 **导出游戏文件（后台）**。导出成功后再安装。

自动配置会切换所有三维视图为实体显示，识别 MMD Base Tex / Principled Base Color 的唯一颜色图，从目标 MTG 中选择支持的简单颜色材质，检测图片透明通道，并设置所有材质。高级手动配置默认折叠。同一张颜色图只编码一次；不要把 Toon 或 Sphere 图当颜色图。

本次 00150 的崩溃日志显示：选中颜.png 后，Blender 5.2.2 在 EEVEE 的 ShaderNodesInliner / GPU_material_from_nodetree 调用中发生访问异常，当时未开始导出。0.3.1 通过实体显示绕开该预览路径，并非修复 Blender 内部着色器编译器。处理此模型时保持实体显示，不要为了查看颜色再次切回材质预览。

如果闪退恢复后的静态副本出现空材质槽，只有在单一原物体与副本的顶点数量、逐面拓扑、材质编号全部一致时才自动恢复。若无法证明对应关系，停止并提示重新制作副本。不会按名称或空间距离猜测，也不删除模型面或修改原 MMD 材质节点。

自动流程目前用于静态展示。遇到不支持的模板、缺图、多个颜色图候选时停止，不保证所有 MMD 都能一键导出。图片透明通道不等于完整的游戏透明效果；球面高光、材质整体透明度和复杂节点仍需单独适配。

本次梦见月瑞希 → 00150：自动识别 20 个材质、4 张颜色图，完整导出及文件回读通过；保存并重开后材质指针保持。髮+ 球面高光只保留颜色，尚未验证游戏内外观。


主要用途：**修改哪个角色，就使用该角色自己的原始资源作为模板，生成对应的同名皮肤替换文件。** 一次导出生成 CMesh、GIM、MTG，以及需要的新贴图，不是只替换一个孤立文件，也不再默认指向 116_01。

同时提供“新皮肤资源”输出方式，用新文件名和新目录生成资源。它不自动在游戏菜单中新增可选皮肤；真正增加入口还需要客户端配置。

## 安装与升级

1. 保存正在编辑的 Blender 场景。
2. 停用旧版“NeoX 皮肤导出与回装”，通过“编辑 → 偏好设置 → 插件 → 从磁盘安装”安装 NeoX_皮肤导出插件_v0.3.2.zip。
3. 升级后重启 Blender，启用插件，防止旧 Python 子模块留在内存中。
4. 三维视图按 N，打开“NeoX 导出”，面板应为 **NeoX 角色皮肤回写 0.3.2**。

声明支持 Blender 4.2 以上，本次实际测试为 Windows Blender 5.2.2 LTS。内置 Windows SSE2 ASTC 编码器。导入仍使用原来的 NeoX 导入插件。

5. **输出用途** 选择“同角色同名回写”；**绑定方式** 选择“保留原角色动作”。同角色改模不需要制作静态副本。
6. 第 1 层 UV 选择 UVMap，第 2 层 UV 选择 UVMap_2。0.3 按原始每个分组的层数写入：原来一层的仍一层，原来两层的保留两层。缺少附加层时停止，不会用零值代替。
7. 点击 **匹配材质来源**，逐项确认原分组。只改几何时选择“保留原游戏材质”。改贴图则选择“替换颜色贴图”并指定图像；复杂节点可使用“烘焙颜色近似”，但光泽、视角效果等不能完全还原。
8. 点击 **检查模型 → 导出游戏文件（后台）**。完成后打开导出文件夹，得到 00129_03.cmesh、00129_03.gim、00129_03.mtg 和所需贴图，目标是 00129_03 自己。

另提供 C:\WORK\Chatgpt\00129_03_同名回写_本地验证.zip，是当前改模的三文件测试包，使用原游戏材质及已有贴图。本地回读已通过，尚未在游戏验证显示和动作。后来继续修改模型时需重新导出。

## 原骨架、权重和顶点颜色

保留原骨架的静止位置、方向、父子关系，以及 neox_source_index 属性。可以改网格、增删面、改变 UV 和调整已有骨骼的权重；每个使用中的顶点要求 1～4 个有效骨骼权重。

原生模式读取静止网格，不会把当前动画姿势再次烘焙进去。几何修改器先在工作副本中应用，骨架修改器保留。

部分模型在 NeoX 导入时经过骨骼索引映射。0.3 对同一导入源核验 SHA-256 后，用同一导入算法的逆映射恢复原始运行时权重索引。来源不符、新增权重指向未能恢复映射的骨骼时会停止。它不是不同角色间的自动骨架适配。

原导入器未暴露的顶点颜色，会依据原分组、位置、UV 和三角形对应关系唯一恢复。相同位置和 UV 但颜色不同的顶点会分开；仍无法唯一确定时停止。不要删除颜色检查后强行导出。

## 多套自制外观与真正新增皮肤入口

### 在现有皮肤位置使用自己制作的新外观

继续用“同角色同名回写”。可保存不同 blend 外观版本，每次导出都放在独立任务目录，它们都能作为该现有皮肤的替换包。原版模板和历史输出保留。

### 生成不同名字的新皮肤资源

1. 使用同角色原始模板建立工程。
2. 输出用途改为 **新皮肤资源（仅生成文件）**。
3. 填写准备在客户端配置中使用的新资源文件名（不带扩展名）和新资源目录，两者须区别于原皮肤。插件不会擅自分配游戏皮肤编号。
4. 按正常流程设置材质、检查并导出。
5. 输出包含新名称的 CMesh/GIM/MTG；新颜色贴图引用指向新目录。沿用的原贴图仍引用原目录，不会把所有原贴图和动作复制成一套独立资产。
6. 查看 registration_manifest.json 和 report.json：记录资源路径、校验值、贴图依赖，以及尚未完成的客户端工作。

**这只是生成资源，尚未让游戏多出一项可选皮肤。** 真正新增入口需要核对并登记皮肤编号、角色归属、局内/局外路径、动作和特效、图标、展示入口及单机版可用列表。0.3 未自动修改这些配置，新资源模式不能通过“同名安装”按钮安装。

本地脚本清单中可见 common_data/hero_fashions_data.nxs、common_data/fashion_items_data.nxs 等候选配置。目前只确认文件名存在，未证明它们就是当前 MuMu 单机版加载的全部配置，也没有实现配置写入。不要仅改文件名就认为新增入口已经完成。

## 材质与贴图

| 选项 | 用法 |
| --- | --- |
| 保留原游戏材质 | 沿用模板 MTG，适合只改网格；不转换 Blender 节点修改 |
| 替换颜色贴图 | 选择 Blender 图像，输出 ASTC，更新克隆材质的颜色纹理 |
| 烘焙颜色近似 | 后台 Cycles 烘焙颜色，以第 1 层 UV 作目标，其他 UV 可继续供节点读取 |

“原分组”以原 GIM 子网格为单位，不是按 Blender 材质槽数字对应。新增材质需要选择合适来源；同一来源可以被多个新材质使用。

ASTC 默认 6×6。烘焙尺寸只影响烘焙图，直接替换图像保留原尺寸。透明、光泽、复杂节点和特效仍需在游戏验证。

## MuMu 安装与恢复

仅用于已解包、读取松散资源的单机客户端，无需重新封装 NPK。

1. 在插件偏好设置确认 C:\GAME\MUMU\MuMuPlayer\nx_main、实例编号和包名 com.netease.fr26。
2. 启动 MuMu，确认目标目录存在。退出游戏进程，或勾选“安装或恢复前关闭游戏”。
3. 同名导出成功后，点击“安装到 MuMu”。它使用工程自己的目录，不固定到 116_01。备份目标文件、暂存上传、核对 SHA-256 后再替换。
4. 重开游戏，进入对应角色、对应皮肤检查模型和动作。安装成功不等于显示验收通过。

提示未知版本时，先确认设备上的确是要保留的现有版本，再用“备份当前版本为基线”备份后安装。

恢复按钮恢复安装前的版本，可能是之前修改版，不总是最初原版。断连导致回滚失败时，恢复连接，选择本工程 device_backups 中对应备份目录，再执行恢复。保留 source 原版快照与备份记录。

也可手动备份后复制本次 files 内全部文件到模拟器。本例目标：

/storage/emulated/0/Android/data/com.netease.fr26/files/netease/frxy/res/char/charselect/00129/fashions/00129_03/

关闭游戏后覆盖同名文件，保留其他资源。不要只复制 CMesh，不要重命名新贴图。手动替换应使用自己的手动备份恢复。

## 工程与限制

一个工程管理一套同名 CMesh/GIM/MTG 及相关导出贴图。如果角色还有尾巴、武器、伙伴等独立 CMesh，需为实际修改的其他 CMesh 分别建工程，不能一律合并后只覆盖主文件。0.3 尚无整目录多 CMesh 自动批处理。

工程含 source 原模板、每次 exports 的场景副本与日志、report.json、files 和 device_backups。未改动的原贴图和动作继续由客户端现有资源提供，输出是替换资源包。

支持 v4、flag 4/5、单分段，每分组 1～4 层 UV、最多一层源顶点颜色，模板骨骼 1～254 根，拆分后总顶点不超过 65535。未保证所有模型兼容。双分段、旧版本、其他布局、新骨架动作或新增皮肤入口需继续单独适配。

外来模型静态副本仍作为可选工具保留，主要用于跨骨架展示，不是同角色回写的必经步骤。
